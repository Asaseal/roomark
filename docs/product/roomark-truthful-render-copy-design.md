# Roomark 概念图文案一致性设计

日期：2026-07-30

## 背景

Roomark 当前的软装页和房源库已经把本地生成结果标记为 `Mock 效果图`，发布指南也明确说明产品不提供真实图片生成服务。但 Android 房源详情页仍使用“AI 效果图”“已生成”和“可生成一张室内效果图”等表述，并展示“后续可导出 PDF 证据包”的未实现承诺。

这不会造成代码崩溃，却会直接损害成熟产品最重要的可信度：同一个本地概念预览在不同页面被描述成不同能力，用户无法判断看到的是本地示意图还是真实 AI 结果。

## 目标

- 让 Android 房源详情页与现有软装页、房源库和发布说明保持一致。
- 明确结果是设备内生成并保存的 `Mock 概念图`。
- 移除未实现的 PDF 导出承诺。
- 不改变现有功能、导航、存储 schema、`RenderPreview` 类型或历史本地数据。

## 非目标

- 不接入真实 AI 图片生成。
- 不实现 PDF 导出。
- 不增加新的按钮、页面、设置或数据字段。
- 不重命名 `renderPreview`、`renderStatus` 等内部持久化字段，避免无价值的数据迁移。

## 方案比较

### 方案 A：只统一用户可见文案

修改 `RoomDetailScreen` 的概念图状态、说明和证据包文本，并增加静态契约测试。优点是风险最低、不会影响持久化数据，且能直接修复用户信任问题。

### 方案 B：同时重命名内部类型和存储字段

将 `renderPreview` 等字段改为更抽象的 `conceptPreview`。语义更纯净，但需要 schema 迁移、兼容旧记录和多页面联动，投入与当前用户收益不成比例。

### 方案 C：接入真实生成或 PDF

可以让现有文案变成事实，但属于用户明确排除的新功能，也会引入网络、账号、成本、隐私和发布风险。

## 决策

采用方案 A。Roomark 继续保留现有本地 Mock 概念图功能，只修复详情页的展示语义。

## 文案规则

房源详情页使用以下稳定语义：

- 分区标题：`模拟与概念图`
- 状态名称：`Mock 概念图`
- 状态值：`已保存` / `未创建`
- 操作说明：`验证家具摆放，并保存概念预览`
- 未生成说明：`摆好家具后，可创建本地概念预览。`
- 已生成说明：`Mock 概念图已保存，可继续调整`
- 证据说明：只描述当前已整理的风险标签、现场备注、软装状态和 Mock 概念图状态，不再承诺 PDF。

## 测试与验收

自动化契约读取 `RoomDetailScreen.tsx`，要求出现 `Mock 概念图` 和本地概念预览说明，并禁止以下误导性表述：

- `AI 效果图`
- `生成效果图`
- `生成一张室内效果图`
- `导出 PDF`

完成后运行 Mobile 全量验证、仓库全量验证和 Android TypeScript 检查。该变更只涉及 React Native 文案，不需要修改原生工程或重新定义产品能力。
