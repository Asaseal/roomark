# Roomark Android 核心触控语义设计

日期：2026-07-30

## 目标

在不改变现有界面、业务流程、导航、数据结构和功能范围的前提下，为 Roomark Android 现场看房流程中的已有触控目标补齐稳定、明确的无障碍语义，使读屏服务和 Android 自动化检查能够识别：

- 这是一个可操作按钮。
- 该按钮会对哪个对象执行什么动作。
- 筛选项或模式当前是否选中。
- 当前不可用的操作是否处于禁用状态。
- 图标按钮、卡片按钮和动态文案按钮的真实用途。

## 当前问题

核心页面已经为保存失败、生成中和部分输入框提供了无障碍属性，但覆盖不一致：

- 首页主操作、房源卡片、地图筛选、返回图标和软装操作大多只有视觉文案或图标。
- `TouchableOpacity` 的可点击性没有在所有位置显式表达为按钮角色。
- 扫描模式和地图筛选缺少 `selected` 状态，读屏无法判断当前选择。
- 房源卡片和地图标记没有稳定表达对象名称、风险、价格或打开后的目标页面。
- 软装工作室中的锁定、重置、删除和 Mock 概念图操作依赖图标或短文案，缺少上下文。

## 方案比较

### 方案 A：只补按钮角色

为所有 `TouchableOpacity` 添加 `accessibilityRole="button"`。改动最小，但不能解决图标含义、动态对象上下文、选中状态和操作后果不清晰的问题。

### 方案 B：补齐角色、动作标签和交互状态

按现有页面逐个补充：

- 显式按钮角色。
- 中文动作标签，优先表达“动作 + 对象”。
- 只有结果不明显时才增加提示。
- 扫描模式和地图筛选增加选中状态。
- 已有不可用操作继续表达禁用状态。
- 房源卡片和地图标记聚合必要的对象摘要。

该方案不改变任何可见布局或业务行为，回归面可控，同时完整覆盖当前缺口。

### 方案 C：重构为统一无障碍按钮组件

把现有触控组件统一替换为新的共享组件。长期一致性更好，但会扩大本轮改动范围，并可能影响样式、按压反馈和现有事件处理，不符合“先完成已有功能、不要新增或扩大改造”的约束。

采用方案 B。

## 语义规则

### 通用规则

- 所有已有触控目标显式设置 `accessibilityRole="button"`。
- 标签使用完整中文动作，不依赖按钮旁边的标题或图标。
- 动态对象需要包含对象名称，例如“打开北岛中庭公寓房源详情”。
- 提示只用于操作结果不能从标签直接判断的场景，例如房源卡片提示“打开房源详情”。
- 不用无障碍标签承载长篇说明；房租、通勤、风险等摘要只保留现场决策需要的信息。
- 不新增隐藏按钮、快捷操作、手势或额外页面。

### 选中与禁用状态

- 扫描模式按钮使用 `accessibilityState={{ selected: ... }}`。
- 地图筛选按钮使用 `accessibilityState={{ selected: ... }}`。
- 地图标记使用选中状态表达当前展开的房源。
- Mock 概念图生成、锁定、重置、删除等现有条件操作保留并补齐 `disabled` 状态。
- 不使用标签文本模拟状态；状态由 `accessibilityState` 单独表达。

### 页面规则

- 房源库：首页动作表达创建扫描、打开地图和打开对比；房源卡片表达房源摘要及详情目标；对比选择与软装入口表达当前对象和动作。
- 房源对比：返回按钮表达返回房源库；房源卡片表达关键决策摘要并指向详情。
- 看房地图：返回、筛选、地图标记、详情和软装入口均提供明确标签；筛选和当前标记表达选中状态。
- 房源详情：返回和开始/继续软装表达明确目标。
- 模拟扫描：返回、手动记录、户型预设模式表达按钮角色和当前选中状态；不改变现有生成与保存语义。
- 软装家具抽屉：家具条目表达“放入 + 家具名称 + 简短描述”。
- 软装工作室：返回按钮明确表达“保存布局并返回房源库”；家具菜单、Mock 概念图、锁定、重置、删除、关闭预览和保存概念图均提供明确语义。
- 3D 加载失败页：重试和退出按钮补充稳定的中文标签，退出目标明确为房源库。

## 实施边界

本轮只修改 React Native 组件的无障碍属性和对应契约测试：

- 不改变可见文字、颜色、布局、触控面积或动画。
- 不改变导航目标、保存时机、按钮可用条件或事件回调。
- 不引入新的共享组件、依赖、权限或原生代码。
- 不改变 Android 包名、版本、签名或发布配置。

## 测试与验收

### 自动化契约

新增源码契约测试，覆盖：

1. 房源库、对比页和详情页的主按钮与房源卡片语义。
2. 扫描模式、地图筛选和地图标记的按钮角色及选中状态。
3. 家具抽屉、软装工作室和 3D 失败页的动作标签及禁用状态。
4. 所有新增标签继续绑定原有回调，不通过新增逻辑替代现有行为。

### Android 模拟器

在 API 34 模拟器上使用 UI Automator 检查核心页面节点：

- 主操作、返回、房源卡片和地图筛选具有稳定 `content-desc`。
- 模式和筛选状态能够在节点属性中区分选中与未选中。
- 禁用操作仍不能触发，且节点表达不可用状态。
- 页面导航、已有记录和软装布局保持可用。
- React Native、AndroidRuntime 和 Chromium 错误日志为 0。

### 发布门槛

Mobile 测试、TypeScript、Expo 配置、Android Debug 构建、release JavaScript bundle 和仓库级验证全部通过后，才允许合入公开 `main`。

物理 Android 设备上的 TalkBack 连续读序、中文播报自然度、真实触控面积和厂商系统兼容性仍是正式发布前的独立验收项；本轮模拟器证据不能替代该门槛。

## 非目标

- 不新增语音控制、TalkBack 教程、设置页或无障碍偏好。
- 不调整视觉设计、字体、颜色对比度或横竖屏布局。
- 不重构触控组件体系。
- 不宣称已经完成物理设备 TalkBack 验收。
