# 房源状态后台重试设计

日期：2026-08-04  
状态：已按 Roomark Looping 授权自行确认

## 问题

房源选择、对比和扫描结果会立即写入同一个本地产品状态。写入失败时，Library 会显示重试入口，但应用离开前台时不会主动重试；如果系统随后终止进程，当前内存中的最新修改可能丢失。

## 方案比较

1. **在 `App` 监听生命周期并重试（采用）**：应用离开 `active` 时，仅在已有写入错误且当前没有写入时调用现有 `retryPersistence`。复用现有最新快照、串行队列、错误提示和 pending 状态，改动小且边界清晰。
2. **在 Zustand Store 内监听 `AppState`（拒绝）**：会把 React Native 生命周期依赖放进数据 Store，增加模块初始化、副作用清理和测试复杂度。
3. **给写入增加超时或定时重试（拒绝）**：AsyncStorage 写入不可取消，超时后放行可能让迟到旧写入覆盖新数据；持续定时重试还会造成不可控耗电与重复 I/O。

## 行为

- `App` 订阅 `AppState.change`。
- 状态离开 `active` 时，如果 `persistenceError` 存在且 `pendingPersistence` 为 `false`，调用一次现有 `retryPersistence`。
- 没有保存错误或已有写入进行中时不触发额外写入。
- 组件卸载时移除订阅。
- 重试始终保存 Store 当前最新快照；成功后沿用现有逻辑清除错误，失败后继续保留错误。
- 不新增后台任务、写入超时、账号、同步或任何产品入口。

## 验证

- 契约测试先证明 `App` 缺少 `AppState` 订阅并失败。
- 实现后验证订阅、条件保护、重试调用和清理。
